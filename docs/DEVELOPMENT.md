# Разработка и дальнейшая работа

SupportFlow создан по техническому списку владельца портфолио с помощью AI-ассистента. Исходный код, тесты и документация не выдаются за полностью самостоятельную работу владельца.

Разработка проходит реальными этапами: Gradle-модули и SQL-схема; JWT и JPA-бизнес-логика; отдельный worker, RabbitMQ и Redis; unit/integration/сквозные проверки; документация и исправления по результатам тестов. Коммиты отражают эти изменения, а pull request сохраняет проверку перед merge.

## Что сделать самостоятельно

1. Запустить Compose и пройти жизненный цикл через Swagger или Postman.
2. Объяснить права CLIENT/SUPPORT/ADMIN и написать дополнительный тест на запрещённое действие.
3. Реализовать SLA deadline с миграцией V2, сортировкой просроченных обращений и тестами времени через Clock.
4. Добавить refresh-token rotation и отзыв сессий, не сохраняя токены в открытом виде.
5. Реализовать контролируемый replay DLQ с аудитом и авторизацией.
6. Проверить EXPLAIN ANALYZE на большом наборе тестовых данных и обосновать новый индекс.
7. Добавить курсорную пагинацию и сравнить её с offset при вставках.

После выполнения фиксируйте собственный вклад конкретно: задача, решение, тесты, ограничение. Не заменяйте это утверждением «знаю все технологии», пока не можете объяснить поведение кода и самостоятельно его изменить.
