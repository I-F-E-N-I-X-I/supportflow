# JVM, отладка и самостоятельные упражнения

Объекты и массивы обычно размещаются в heap, локальные переменные и контекст вызова — в stack frames потоков. Ссылочная переменная хранит ссылку, а не копию объекта. Примитивные поля могут находиться внутри объектов heap; оптимизации JIT способны устранять выделение, поэтому правило «все примитивы всегда на стеке» неверно. Сборщик мусора освобождает недостижимые объекты, но не заменяет закрытие потоков, соединений и executor.

Static-ссылки и долгоживущие коллекции могут удерживать объекты. Кэш без TTL/ограничения размера приводит к росту памяти. Рекурсия использует стек; граф с циклом требует visited-set. `volatile` даёт видимость записи, но не делает `counter++` атомарным; для составного изменения в примере используется synchronized. Блокировка Java-объекта работает только внутри одной JVM; согласованность нескольких API-инстансов обеспечивает PostgreSQL.

В IntelliJ IDEA откройте корневой settings.gradle, выберите JDK 21 и импортируйте Gradle. Для отладки тестов поставьте breakpoint в Status.transitionTo, TicketService.create или Algorithms.binarySearch и запустите соответствующий тест через Debug. Используйте Step Into/Over, Watches и Evaluate Expression. Для интеграционных тестов нужен Docker.

Упражнения: предскажите результат `new String("x") == new String("x")`; объясните изменение массива после передачи в метод; добавьте крайние случаи для binarySearch; сравните O(n²) перебор пар с two pointers; объясните rollback outbox при ошибке истории; воспроизведите конфликт version двумя клиентами. После изменения запустите регрессионные тесты.
